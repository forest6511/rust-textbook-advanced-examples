長めのコンテンツを並べて、パース時間を稼ぎます。Rust の所有権モデルでは、データを「所有する」「借りる」「移動する」の三つの操作を区別します。

並行プログラミングでは、共有状態へのアクセスをどう調停するかが鍵になります。Mutex でクリティカルセクションを直列化する方法、メッセージパッシングで状態を 1 つの所有者に集約する方法、不変な値を Arc で共有する方法、それぞれのトレードオフを把握する必要があります。

非同期 I/O は CPU を待たせず多数の接続を捌くために生まれました。Tokio は Rust 標準の非同期ランタイムで、cooperative scheduling と work-stealing executor で多数の Future を効率よく実行します。

データ並列の rayon は CPU bound 処理を分割統治で並列化します。par_iter で逐次イテレータを並列に切り替え、ワーカースティーリングで負荷を均す仕組みです。

Web クローラはこれらの組み合わせで成り立ちます。HTTP I/O は async、HTML パースは CPU bound、SQLite 書き込みはブロッキング I/O です。各部品をどのプリミティブで扱うかが設計判断の核心です。
